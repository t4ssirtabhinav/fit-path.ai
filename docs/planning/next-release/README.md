## Cross-cutting notes worth keeping in mind when prioritizing

- **Ticket #8 in this batch duplicates ticket #17 from the prior roadmap** (`docs/planning/05-content-ai-plans-personalization.md`) — doc 03 here cross-references rather than re-designing it, to keep the two roadmaps consistent.
- **Doc 02 (mobile) is the structural prerequisite for several other tickets in this batch**: true push notifications (#3, doc 03), offline-first logging's strongest use case (#7, doc 04), and native health-data sync (#5/#6, doc 02 itself) all assume the native app exists. Recommend treating the mobile build as the anchor project this release is sequenced around — not one feature among eighteen.
- **Doc 04 contains a cost-saving reframing worth flagging explicitly**: ticket #11 ("health data encryption") was researched against Supabase's own published guidance, which actively recommends *against* column-level `pgcrypto` encryption for most cases (citing key-management complexity and broken indexing) in favor of the encryption-at-rest + RLS combination Supabase already provides. The actionable work is an **RLS policy audit**, not an encryption-implementation project — a meaningfully smaller and lower-risk scope than the ticket's framing implied.
- **Docs 07 and 08 should be sequenced together**: DPIIT/Startup India registration (the gateway credential in doc 08) depends on the company being incorporated first (doc 07), and the MSME/Udyam registration that unlocks the discounted trademark fee (doc 07) is the same registration that unlocks several funding-program eligibility checks (doc 08).
- **Doc 06 (menstrual cycle tracking) is flagged as the single highest-stakes research area in this batch** — it sits at the intersection of categorically-sensitive health data, contested exercise science, and real legal exposure in some jurisdictions. It's the one topic in this release where a brief consult with someone with relevant legal/compliance expertise is recommended before committing to a design, beyond the web research collected here.
- **Doc 05's "AI-generated video" idea is deliberately scoped as an optional experiment, not a commitment** — the doc recommends shipping a complete exercise library via existing datasets (ExerciseDB/Wger) first, and treating Veo/Nano-Banana-generated clips as a small, budget-capped pilot to validate before any larger investment — directly honoring the ticket's own "rate and cost limiting" instinct.
- **This research is more time-sensitive than the prior roadmap's** — AI model names/pricing (doc 05), app-store policies (doc 02), and government scheme details (docs 07/08) all move quickly. Each doc carries its own "re-verify before acting" note; take those seriously given how much of this batch touches compliance and platform-policy surfaces that change without much notice.
